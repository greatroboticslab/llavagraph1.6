# Pipeline Documentation

## Overview

This document describes the complete data pipeline, input features, and the
mathematical formulas used to compute the CORRECTION VECTOR analytically.

---

## Complete Pipeline

```
Step 1  Raw hardware data (CSV files from piezo actuator)
           |
           v  process_raw_8.py  (signal processing, FFT, quarter analysis)
Step 2  features_full.csv  (493 samples × 57 features)
           |
           +---> build_feature_text()  -->  formatted text input (JSONL "input" field)
           |
           +---> compute_correction_vector()  -->  CORRECTION VECTOR (math formulas)
           |
           +---> PNG waveform image + feature text  -->  Gemini Vision API
           |                                              --> DIAGNOSIS + CORRECTION text
           v
Step 3  training_data.csv  (input text + LLM-generated description + CV)
           |
           v  prepare_data.py
Step 4  train.jsonl  (1468 samples)
        val.jsonl   (490 samples)
        test.jsonl  (487 samples)
           |
           v  infer_zamba.py / finetune_zamba.py
Step 5  Zamba2-7B-instruct generates DIAGNOSIS + CORRECTION
        CORRECTION VECTOR appended analytically (100% accurate)
```

**Key point:** The DIAGNOSIS and CORRECTION text in training labels were generated
by **Gemini Vision API** (gemini-2.5-flash), not written by humans. Gemini received
both the waveform PNG image and the extracted feature text, then produced the
diagnostic paragraphs. Zamba2 is trained to reproduce this format and quality.

---

## Input Features

Each sample fed to Zamba2 during inference is a formatted text block built from
`features_full.csv`. The raw CSV columns are extracted from hardware measurements
using FFT, quarter-window analysis, and signal fitting.

### What the model receives (example — sine at 100 Hz)

```
COMMANDED WAVEFORM: sine at 100.0 Hz, target peak ±495.8 nm

IDEAL REFERENCE for this waveform type:
  THD: 0%
  sine-fit residual: 0%
  crest factor: 1.414
  even harmonics: 0
  FOPDT predicted phase lag: 9.11° (any excess is nonlinear distortion)
  FOPDT predicted attenuation: 0.9879

MEASURED FEATURES (480-740 ms window):
  Dominant frequency (Hz): 100.0
  RMS displacement (nm):   206.7
  Peak displacement (nm):  495.8
  THD (%):                 3.631
  Crest factor:            2.398
  2nd harmonic ratio:      0.01052
  3rd harmonic ratio:      0.01873
  Phase lag (deg):         76.1
  Amplitude drift Q1→Q4 (nm): 74.86
  Hysteresis (nm):         18.62
  ...
```

### Feature definitions

| Feature | Source | Physical meaning |
|---------|--------|-----------------|
| `dominant_freq_hz` | FFT peak | Actual output frequency |
| `rms_nm` | Time-domain RMS | Overall signal energy |
| `peak_nm` | Time-domain max | Maximum displacement achieved |
| `thd_pct` | FFT harmonics | Total Harmonic Distortion — how far from ideal |
| `crest_factor` | peak/RMS | Shape factor (ideal sine = 1.414, ideal square = 1.0) |
| `harmonic_ratio_2` | H2/H1 amplitude | 2nd harmonic contamination |
| `harmonic_ratio_3` | H3/H1 amplitude | 3rd harmonic contamination |
| `sine_phase_lag_deg` | sine fit | Phase lag between commanded and measured |
| `fopdt_phase_lag_deg` | linear model | Phase lag predicted by linear FOPDT model |
| `amplitude_drift_nm` | Q4 peak − Q1 peak | Temporal creep/drift over measurement window |
| `hysteresis_nm` | half-cycle asymmetry | Piezo hysteresis width |
| `square_duty_cycle` | zero-crossing ratio | Fraction of period above zero |
| `square_edge_sharpness` | 10%–90% rise time | How sharp the transitions are (1.0 = ideal) |
| `ramp_rise_linearity` | linear fit R² | How linear the rising ramp is (1.0 = ideal) |
| `spectral_flatness` | geometric/arithmetic mean | How flat the noise spectrum is (1.0 = white noise) |

**FOPDT** = First Order Plus Dead Time — the standard linear model for piezo actuators.
Any phase lag or attenuation beyond the FOPDT prediction is pure nonlinear distortion.

## Correction Vector Formulas

The CORRECTION VECTOR is **not generated by the LLM**. It is computed from the
measured features using closed-form mathematical formulas. This is why it is
100% accurate regardless of the quality of the LLM text output.

### Sine

| Field | Formula | Physical meaning |
|-------|---------|-----------------|
| `phase_offset_deg` | `−phase_lag` | Negate measured lag → cancel it at the actuator input |
| `amplitude_scale` | `(peak / √2) / RMS` | Ratio of ideal RMS to measured RMS. Ideal sine: RMS = peak/√2 |
| `harmonic_2_amp` | `−h2_ratio` | Negate 2nd harmonic ratio → feedforward cancellation |
| `harmonic_3_amp` | `−h3_ratio` | Negate 3rd harmonic ratio → feedforward cancellation |
| `dc_offset_nm` | `−mean(Q1..Q4 mean)` | Negate average DC drift across quarters |
| `hysteresis_ff_nm` | `−hysteresis_nm` | Negate measured hysteresis width → feedforward pre-distortion |

**Example (sine at 100 Hz):**
```
phase_lag = 76.1°           →  phase_offset_deg = -76.1°
peak = 495.8 nm, RMS = 206.7 nm
  ideal_RMS = 495.8 / √2 = 350.5 nm
  amplitude_scale = 350.5 / 206.7 = +1.6958
h2 = 0.01052                →  harmonic_2_amp = -0.01052
h3 = 0.01873                →  harmonic_3_amp = -0.01873
hysteresis = 18.62 nm       →  hysteresis_ff_nm = -18.62
```

### Square

| Field | Formula | Physical meaning |
|-------|---------|-----------------|
| `duty_cycle_trim` | `0.5 − duty_cycle` | Difference from ideal 50% duty cycle |
| `edge_sharpness_deficit` | `1.0 − edge_sharpness` | Deficit from ideal sharp transition |
| `harmonic_2_amp` | `−h2_ratio` | Cancel even harmonics (ideal square has none) |
| `dc_offset_nm` | `−mean(Q1..Q4 mean)` | Negate DC drift |

**Example (square at 100 Hz):**
```
duty_cycle = 0.4763         →  duty_cycle_trim = 0.5 − 0.4763 = +0.0237
edge_sharpness = 0.9166     →  edge_sharpness_deficit = 1.0 − 0.9166 = +0.0834
h2 = 0.02587                →  harmonic_2_amp = -0.02587
```

### Ramp

| Field | Formula | Physical meaning |
|-------|---------|-----------------|
| `rise_linearity_correction` | `1.0 − rise_linearity` | Deficit from perfectly linear rise |
| `fall_linearity_correction` | `1.0 − fall_linearity` | Deficit from perfectly linear fall |
| `asymmetry_correction` | `−rise_fall_asymmetry` | Negate rise/fall timing asymmetry |
| `amplitude_scale` | `(peak / √3) / RMS` | Ideal sawtooth: RMS = peak/√3 |
| `dc_offset_nm` | `−mean(Q1..Q4 mean)` | Negate DC drift |

### Pulse

| Field | Formula | Physical meaning |
|-------|---------|-----------------|
| `ringing_suppression_target` | `pulse_ringing_ratio` | Target ringing level to suppress |
| `pulse_duty_cycle_measured` | `pulse_duty_cycle` | Measured on-time fraction |
| `amplitude_scale` | `peak / RMS` | Pulse amplitude compensation |
| `dc_offset_nm` | `−mean(Q1..Q4 mean)` | Negate DC drift |

### Noise

| Field | Formula | Physical meaning |
|-------|---------|-----------------|
| `whitening_required` | `1.0 − spectral_flatness` | How much spectral shaping is needed (0 = already white) |
| `rms_measured_nm` | `RMS` | Measured RMS for amplitude matching |
| `gaussianity_error` | `noise_gaussianity_err` | Deviation from Gaussian distribution |
| `autocorr_lag1` | `noise_autocorr_lag1` | Temporal correlation at lag 1 |

## Data Files

| File | Description |
|------|-------------|
| `../data/` | Raw CSV files from piezo actuator hardware |
| `../mamba_llm/features_full.csv` | 493 samples × 57 extracted features |
| `../mamba_llm/training_data.csv` | Generated training data (features + Gemini text + CV) |
| `../mamba_llm/data/train.jsonl` | 1468 training samples (JSONL format) |
| `../mamba_llm/data/val.jsonl` | 490 validation samples |
| `../mamba_llm/data/test.jsonl` | 487 test samples |
| `results/eval_results.jsonl` | Zamba2 inference results (generated on cluster) |

## Source Scripts

| Script | What it does |
|--------|-------------|
| `../mamba_llm/generate_training_data.py` | Extracts features + calls Gemini + computes CV → training_data.csv |
| `../mamba_llm/prepare_data.py` | Splits training_data.csv → train/val/test JSONL |
| `infer_zamba.py` | Few-shot inference (no fine-tuning) |
| `finetune_zamba.py` | LoRA fine-tuning on train.jsonl |
| `infer_finetuned.py` | Inference using fine-tuned LoRA adapter |
| `eval_zamba.py` | Full evaluation on 487 test samples |
